# BallSpot v1.4 — Tournament Lobby + Cleanup UX + Marker Polish

## Overview

This sprint adds tournament lifecycle management (lobby → active → completed/cancelled), a profile screen, and polishes the guess/result marker UX so placing a guess feels like dropping the missing ball, and the reveal image shows the real ball naturally.

---

## Part A — Tournament Lifecycle

### A1. Status Model

`League.status` transitions:

```
lobby → active → completed
             ↘ cancelled
```

- **lobby**: Created but not started. Members can join. No rounds yet.
- **active**: Owner started it. Rounds generated. Members play.
- **completed**: All members have answered all rounds (or a future scheduled task marks it complete). Currently: expose progress data so mobile can show completed state when the current user has no rounds left.
- **cancelled**: Owner cancelled. Hidden from normal lists. No hard-delete of rounds/guesses.

**Default on create:** `lobby`

No migration needed for the `status` column — it already exists in `$fillable`. The schema just needs to recognise the new values. Existing rows with `status = 'active'` remain valid.

### A2. New Backend Endpoints

| Method | Route | Auth | Description |
|--------|-------|------|-------------|
| `POST` | `/api/leagues/{league}/start` | Owner only | Validate, generate rounds, set active |
| `DELETE` | `/api/leagues/{league}` | Owner only | Soft-cancel (set cancelled) |
| `GET` | `/api/profile/stats` | Authenticated | User's stats |

### A3. `LeagueService` Changes

**`create()`**
- Status = `lobby`
- Do NOT call `generateRounds()`
- Do NOT set `starts_at` or `ends_at`

**`start(League $league, int $userId)`** (new)
- Assert caller is owner, league is in lobby
- Assert at least 1 member
- Assert active football challenges exist (fail with 422 + message if not)
- Call `generateRounds($league, $totalRounds)` (existing logic)
- Update: `status = active`, `starts_at = now()`, `ends_at = now() + duration_days days`

**`cancel(League $league, int $userId)`** (new)
- Assert caller is owner
- Update: `status = cancelled`

### A4. `LeagueController` Changes

**`index()`**
- Return only non-cancelled leagues for the current user
- Include `is_owner`, per-user progress fields in resource

**`join()`**
- Assert league status is `lobby`; 422 with clear message otherwise

**`start()`** (new action)
- Delegates to `LeagueService::start()`

**`destroy()`** (new action)
- Delegates to `LeagueService::cancel()`

### A5. `LeagueResource` Response Shape

Add to the response:

```json
{
  "id": 1,
  "name": "Friday Squad",
  "join_code": "ABC123",
  "status": "lobby",
  "owner_user_id": 5,
  "is_owner": true,
  "members_count": 3,
  "rounds_count": 0,
  "completed_rounds_count": 0,
  "remaining_rounds_count": 0,
  "progress_pct": 0,
  "starts_at": null,
  "ends_at": null,
  "members": [...]
}
```

`is_owner` is computed per-request using `$request->user()->id === $this->owner_user_id`.

`completed_rounds_count` and `remaining_rounds_count` are scoped to the current user (same logic as `currentRound`).

**Note:** Resource needs `$request` passed. Use `$this->resource->rounds()->count()` to avoid extra queries when the relation is already loaded.

### A6. Profile Stats Endpoint

`GET /api/profile/stats` returns:

```json
{
  "tournaments_count": 5,
  "completed_tournaments_count": 2,
  "guesses_count": 14,
  "total_score": 680,
  "average_score": 48.6
}
```

Implement in `AuthController::stats()` or a dedicated `ProfileController`. Use DB aggregates, not collection iteration.

## Part C — Marker UX Polish

### C1. Marker Types in ImageGuessPicker

Extend `Marker` interface:

```ts
export interface Marker {
  x_ratio: number;
  y_ratio: number;
  type: 'ghost-ball' | 'glow' | 'default';
  color?: string;
  label?: string;
}
```

**ghost-ball** (user's guess):
- Semi-transparent white border
- Football emoji centered
- Opacity ~0.65
- Size: 42px
- Background: transparent or very light blue tint (e.g. `rgba(255,255,255,0.1)`)
- Shadow for visibility on dark/light images

**glow** (correct ball position, reveal image):
- Transparent center (backgroundColor: 'transparent')
- Border: 3px neon green (`#00E676` or theme `colors.success`)
- Box shadow / `elevation` glow
- Size: ~60px (larger to surround real ball without covering it)
- Opacity: 0.75

**default** (fallback):
- Existing behaviour (filled colored circle)

### C2. GuessScreen (interactive marker)

When user taps image, `ImageGuessPicker` internal `guess` state shows a **ghost-ball** style marker:
- Football ⚽ emoji, opacity 0.65, white border, subtle shadow
- Size 42px, centered on tap point

Label below image changes from coordinates to:
- No guess: `"Tap the image to place your guess"`
- Has guess: `"✓ Guess placed — tap again to adjust"`

### C3. ResultScreen (reveal image)

When `reveal_image_url` exists:

```tsx
markers={[
  {
    x_ratio: result.guess_x_ratio,
    y_ratio: result.guess_y_ratio,
    type: 'ghost-ball',
  },
  {
    x_ratio: result.ball_x_ratio,
    y_ratio: result.ball_y_ratio,
    type: 'glow',
  },
]}
```

When `reveal_image_url` is null (hidden image):
- `ghost-ball` for guess
- `default` (more visible green ring/circle) for correct position — because the real ball isn't visible

### C4. Legend Update

```
⚽ Your guess       [ghost-ball icon]
○  Ball position    [glow ring icon]
```

If reveal image: add small text `"Real ball visible in photo"`
If no reveal: add small text `"Marker shows correct ball position"`

## Architecture Notes

- Keep `League` model/routes unchanged in backend
- Mobile UI says "Tournament" wherever "League" appeared for users
- `currentRound` endpoint: only called for `active` tournaments, not `lobby`
- `LeagueResource` uses `$request->user()` via `$request` in `toArray($request)` — Laravel passes this automatically
- `ProfileController` or inline `AuthController` method — keep it simple, single controller method

- Starting a tournament → status=active, rounds generated
- Start fails if non-owner
- Start fails if no active challenges
- Join lobby → success
- Join active/completed/cancelled → 422
- Cancel → status=cancelled

## Known Limitations

- Completed status is inferred on mobile (remaining_rounds_count === 0) — no server-side auto-complete trigger yet
- No push notifications for tournament start
- No pagination on leagues list (acceptable for MVP)
- Profile stats query is simple aggregate — no caching
